## 秘匿計算とは

$n$ 人の参加者 $P_1, \dots, P_n$ がそれぞれ入力 $x_1, \dots, x_n$ を持っている。全員が知りたいのは $y = f(x_1, \dots, x_n)$ の値だけであり、**自分の入力は誰にも見せたくない**。この要求を満たす技術を**秘匿計算 (secure computation)**、参加者が 3 人以上の一般の場合を**秘密計算 / マルチパーティ計算 (secure multi-party computation, MPC)** という。

いちばん簡単な実現方法は、全員が信頼する第三者を雇って、そこに入力を預けて計算してもらうことである。秘匿計算とは、**この第三者を暗号技術で消し去ること**にほかならない。

![信頼できる第三者に預ける理想世界と、参加者どうしの通信だけで同じ出力を得る現実世界](/img/mpc-overview.svg)

### 安全性の定義

「入力が漏れない」を厳密にするには、上の 2 つの世界を突き合わせる。攻撃者が現実世界のプロトコルで見るものすべて (受け取ったメッセージ、自分の乱数、自分の入力・出力) を**ビュー (view)** という。

<Hint level="info">
  プロトコルが安全であるとは、**任意の攻撃者のビューを、理想世界で得られる情報 (自分の入力と最終的な出力 $y$)
  だけから、多項式時間のシミュレータが生成できる**ことをいう。

ビューが「出力から作り直せてしまう」なら、そのビューには出力以上の情報が入っていない。これを**シミュレーションパラダイム**という。

</Hint>

この定義には「$y$ そのものから漏れる情報」は含まれないことに注意したい。たとえば $f$ が平均値なら、$n - 1$ 人が結託すれば残り 1 人の入力は $y$ から逆算できる。**それはプロトコルの欠陥ではなく、関数の選び方の問題**である。

### 脅威モデル

何を守るかの前に、誰から守るかを決める必要がある。

| 軸               | 選択肢                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| 攻撃者の行動     | **semi-honest** (プロトコルには従うが盗み見る) / **malicious** (任意に逸脱する)                       |
| 結託する人数     | **正直者多数 (honest majority)** $t < n/2$ / **不正者多数 (dishonest majority)** $t < n$              |
| 安全性の根拠     | **情報理論的安全性** (計算能力が無限でも破れない) / **計算量的安全性** (素因数分解などの困難性に依存) |
| 結託相手の決め方 | **静的 (static)** (開始前に決まる) / **適応的 (adaptive)** (実行中に選べる)                           |

semi-honest かつ正直者多数なら情報理論的に安全なプロトコルが作れるが、不正者多数では計算量的仮定が避けられない。実務ではまず semi-honest で設計し、後からゼロ知識証明や MAC を足して malicious 耐性を得ることが多い。

<Hint level="info">
  暗号化との違いを押さえておきたい。通常の暗号は**保管中・通信中**のデータを守るが、計算するときは必ず一度復号する。
  秘匿計算が守るのは**計算している最中**であり、平文が姿を現す瞬間をなくす。

主な応用は、複数の病院が患者データを出さずに統計を取る、複数社が価格を明かさずに入札する、
複数の銀行が顧客リストを見せずに共通の不正利用者だけを見つける、といった「データを寄せられないが答えは欲しい」場面である。

</Hint>

## 有限体の上で計算する

以降、値はすべて素数 $p$ を法とする有限体 $\Bbb{Z}_p$ の元として扱う。理由は 2 つある。

- **範囲から情報が漏れないため**。整数のまま「$x = x_1 + x_2$ と分割する」と、$x_1$ の大きさから $x$ の大きさが推測できてしまう。$\Bbb{Z}_p$ 上なら $x_1$ を一様乱数に取れて、何も漏れない
- **除算まで閉じているため**。後で見るラグランジュ補間は割り算を使う。$\Bbb{Z}_p$ が体であること、つまり $0$ 以外のすべての元に逆数があることが本質的である

### モジュラ逆数

**モジュラ逆数 (modular multiplicative inverse)** とは、互いに素な整数 $a, m$ に対して

$$
ax \equiv 1 \pmod{m}
$$

を満たす整数 $x$ のことである。$\gcd(a, m) = 1$ のときに限り存在し、$\bmod m$ で一意に定まる。求め方は 2 通りある。

- **拡張ユークリッドの互除法**: $ax + my = \gcd(a, m) = 1$ を満たす $(x, y)$ を求める。$O(\log m)$ で、$m$ が素数でなくても使える
- **フェルマーの小定理**: $m = p$ が素数なら $a^{p-1} \equiv 1$ なので $x = a^{p-2} \bmod p$。繰り返し二乗法で $O(\log p)$

Python なら組み込みの `pow(a, -1, m)` がそのままモジュラ逆数を返す。

### 中国剰余定理

**中国剰余定理 (Chinese Remainder Theorem, CRT)** とは、対ごとに互いに素な整数 $m_1, m_2, \dots, m_n$ に対する連立合同式

$$
\begin{aligned}
x &\equiv a_1 \pmod{m_1} \\
x &\equiv a_2 \pmod{m_2} \\
&\vdots \\
x &\equiv a_n \pmod{m_n}
\end{aligned}
$$

が $\bmod M = \prod_i m_i$ で一意な解をもつ、という定理である。解は

$$
x \equiv \sum_{i=1}^{n} a_i M_i N_i \pmod{M}
\quad \text{where} \quad
M_i = \frac{M}{m_i}, \quad N_i = M_i^{-1} \bmod m_i
$$

で求められる。$M_i$ は $m_i$ 以外のすべての法で $0$ になり、$M_i N_i$ は $m_i$ を法として $1$ になるので、右辺は確かに $i$ 番目の式を満たす。**モジュラ逆数 $N_i$ を忘れると成り立たない**ので注意したい。

秘匿計算の文脈で CRT が効いてくる場面は次のとおりである。

- **大きな法での計算の分解**: $\Bbb{Z}_M$ 上の計算を、小さな $\Bbb{Z}_{m_i}$ 上の独立な計算に分けて並列化する
- **RSA・Paillier の復号の高速化**: $\bmod n$ でのべき乗を $\bmod p$ と $\bmod q$ に分けると約 4 倍速くなる
- **CRT に基づく秘密分散**: Asmuth–Bloom や Mignotte の閾値法は、$x \bmod m_i$ をシェアとして配る

## 加法的秘密分散

もっとも簡単な**秘密分散 (secret sharing)** は、秘密 $s \in \Bbb{Z}_p$ を「足すと $s$ になる $n$ 個の乱数」に分けることである。$s_1, \dots, s_{n-1}$ を一様乱数に取り、

$$
s_n = s - (s_1 + \dots + s_{n-1}) \bmod p
$$

とする。以降、$s$ が $n$ 個のシェアに分散されている状態を $[s]$ と書く。

![秘密を Z_p 上の 3 つの弧に分ける様子と、シェア 1 つの分布が秘密によらず一様であること](/img/mpc-additive-sharing.svg)

```python
P = (1 << 61) - 1  # メルセンヌ素数

def additive_share(secret, n, rng, p=P):
    """足すと secret になる n 個のシェアを返す。"""
    shares = [rng.randrange(p) for _ in range(n - 1)]
    shares.append((secret - sum(shares)) % p)
    return shares
```

安全性は**ワンタイムパッドそのもの**である。$n - 1$ 個以下のシェアはすべて一様乱数で、秘密とは統計的に独立である。左の図のように、$s = 21$ と $s = 5$ では $(s_1, s_2)$ の取りうる集合こそ違うが、$s_1$ だけを見た分布はどちらも $\Bbb{Z}_{32}$ 上の一様分布で、区別がつかない。これは計算量的仮定に依らない**情報理論的安全性**である。

<Details title="シェア 1 つが秘密と独立であることの証明">

$n = 2$ で示す ($n > 2$ も同様)。秘密 $s$ に対し $s_1$ は一様乱数、$s_2 = s - s_1$ である。任意の $s$ と任意の値 $v \in \Bbb{Z}_p$ に対して

$$
\Pr[s_1 = v \mid \text{秘密} = s] = \Pr[s_1 = v] = \frac{1}{p}
$$

であり、$s_2$ についても $\Pr[s_2 = v \mid \text{秘密} = s] = \Pr[s_1 = s - v] = 1/p$ となる。どちらも $s$ に依存しない。したがって攻撃者が片方のシェアを見ても、秘密の事後分布は事前分布のままである。

</Details>

この分散法の何よりの美点は**線形性**である。$[x]$ と $[y]$ のシェアを持つ各参加者が

$$
z_i = x_i + y_i \bmod p, \qquad w_i = c \cdot x_i \bmod p
$$

をローカルに計算するだけで、$[x + y]$ と $[cx]$ のシェアができあがる。**加算と定数倍は通信ゼロで済む**。定数の加算 $[x] + c$ だけは、二重に足さないよう $P_1$ だけが行う。

## Shamir の秘密分散

加法的秘密分散には弱点がある。$n$ 個のシェアが全部そろわないと復元できないので、**1 人でも欠けると秘密が永久に失われる**。$n$ 個中どの $k$ 個からでも復元でき、$k - 1$ 個では何も分からない、という融通が欲しい。これが**$(k, n)$ 閾値秘密分散**であり、Shamir (1979) の構成が有名である。

アイデアは「$k$ 点あれば $k - 1$ 次多項式が定まる」という補間の一意性そのものである。

1. $a_1, \dots, a_{k-1}$ を一様乱数に取り、$f(x) = s + a_1 x + \dots + a_{k-1} x^{k-1}$ とおく
1. 相異なる $x_i \neq 0$ を選び、$P_i$ にシェア $(x_i, f(x_i))$ を渡す (ふつう $x_i = i$)
1. 復元は、任意の $k$ 個のシェアからラグランジュ補間で $f(0) = s$ を求める

![2 次多項式による分散と、3 点からのラグランジュ補間による復元](/img/mpc-shamir.svg)

ラグランジュ補間は、$x = 0$ での値だけが欲しいので次のように簡単になる。

$$
s = f(0) = \sum_{i \in S} y_i \lambda_i, \qquad \lambda_i = \prod_{j \in S, \, j \neq i} \frac{0 - x_j}{x_i - x_j} = \prod_{j \in S, \, j \neq i} \frac{x_j}{x_j - x_i}
$$

係数 $\lambda_i$ は $y_i$ に依存せず、**どの $k$ 人が集まるかだけで決まる**。ここが後で効いてくる。

```python
def share(secret, n, k, rng, p=P):
    """(k, n) 閾値秘密分散。シェア (i, f(i)) を n 個返す。"""
    coeffs = [secret] + [rng.randrange(p) for _ in range(k - 1)]
    shares = []
    for i in range(1, n + 1):
        y, x_pow = 0, 1
        for c in coeffs:  # ホーナー法でもよい
            y = (y + c * x_pow) % p
            x_pow = x_pow * i % p
        shares.append((i, y))
    return shares


def reconstruct(shares, p=P):
    """ラグランジュ補間で f(0) を求める。shares は k 個あればよい。"""
    total = 0
    for i, (xi, yi) in enumerate(shares):
        num, den = 1, 1
        for j, (xj, _) in enumerate(shares):
            if i != j:
                num = num * (-xj) % p
                den = den * (xi - xj) % p
        total = (total + yi * num * pow(den, -1, p)) % p
    return total
```

### なぜ $k - 1$ 個では何も分からないのか

実数上で考えると直感的である。2 次多項式に対して 2 点しか知らなければ、$f(0)$ をどんな値に決めても、その 3 点を通る 2 次多項式がちょうど 1 本引ける。

![2 点を通る 2 次多項式は f(0) をどの値にも取れること、および GF(31) 上での数え上げ](/img/mpc-shamir-security.svg)

有限体上ならこれが厳密な議論になる。右の図は $\mathrm{GF}(31)$ 上で $k = 3$ とし、シェアを 2 個知っている状況で、候補となる秘密 $s$ ごとに整合する多項式の本数を全探索で数えたものである。**どの $s$ に対してもちょうど 1 本**なので、秘密の事後分布は一様分布のままになる。

<Details title="一般の k での証明">

攻撃者が $k - 1$ 個のシェア $(x_i, y_i)_{i \in T}$, $|T| = k - 1$ を知っているとする。任意に固定した候補 $s^{\ast} \in \Bbb{Z}_p$ に対して、

$$
f(0) = s^{\ast}, \qquad f(x_i) = y_i \; (i \in T)
$$

は $k$ 個の相異なる点における値の指定なので、$k - 1$ 次以下の多項式がちょうど 1 つ定まる (ヴァンデルモンド行列が正則であることによる)。

多項式は係数 $(a_1, \dots, a_{k-1})$ を一様に選んで作られるから、どの多項式も確率 $p^{-(k-1)}$ で等しく現れる。よって

$$
\Pr[\text{秘密} = s^{\ast} \mid \text{観測}] = \frac{p^{-(k-1)}}{\sum_{s' \in \Bbb{Z}_p} p^{-(k-1)}} = \frac{1}{p}
$$

となり、$s^{\ast}$ に依存しない。攻撃者は $k - 1$ 個のシェアから、秘密について**エントロピーを 1 ビットも減らせない**。

</Details>

<Hint level="warn">
  この安全性は「シェアが秘密と同じ大きさ ($\log p$ ビット)
  ある」ことに支えられている。
  実は情報理論的に安全な秘密分散では、**シェアのサイズは秘密のサイズ以上でなければならない**ことが証明できる。
  「秘密を小さく分割して配る」ことは原理的にできない。
</Hint>

### 2 つの分散法の比較

|                | 加法的秘密分散         | Shamir                |
| -------------- | ---------------------- | --------------------- |
| 復元に必要な数 | $n$ 個すべて           | 任意の $k$ 個         |
| 耐障害性       | なし                   | $n - k$ 人まで脱落可  |
| シェア生成     | 乱数 $n - 1$ 個        | 多項式評価 $O(nk)$    |
| 加算・定数倍   | ローカル               | ローカル              |
| 乗算           | Beaver triple が必要   | 次数低減が必要        |
| 主な用途       | 不正者多数 (SPDZ など) | 正直者多数 (BGW など) |

## 秘密分散に基づく秘匿計算

秘密分散が用意できたら、あとは**関数を加算と乗算の回路として書いて、シェアのまま 1 ゲートずつ評価していく**だけである。$\Bbb{Z}_p$ 上の加算と乗算があれば任意の関数が表現できるので、これで原理的にはすべての秘匿計算ができる。この路線を確立したのが BGW プロトコル (Ben-Or–Goldwasser–Wigderson, 1988) である。

### 加算はただである

すでに見たとおり、Shamir シェアでも $f$ と $g$ を足せば $(f + g)(0) = x + y$ なので、各者が自分のシェアを足すだけでよい。**通信は発生しない**。

### 乗算は次数を倍にする

問題は乗算である。各者が $f(i) \cdot g(i)$ を計算すると、これは積多項式 $h = fg$ の $i$ での値になっており、$h(0) = xy$ は確かに正しい。しかし $h$ の次数は $2t$ に増えてしまう。

![シェアの積は次数 2t の多項式のシェアになり、復元には 2t+1 点が必要になる](/img/mpc-degree.svg)

このまま乗算を繰り返すと次数が $2t, 4t, 8t, \dots$ と倍々に増え、$n$ 個のシェア全部でも足りなくなる。さらに困ったことに、$h$ の係数は独立な乱数ではない (先頭係数は $f$ と $g$ の先頭係数の積で、$0$ になりうる) ので、**正しく乱択された次数 $2t$ のシェアですらない**。

そこで乗算のたびに**次数低減 (degree reduction)** を行う。$n \ge 2t + 1$ であれば次のようにできる。

1. 各 $P_i$ が積 $v_i = f(i) g(i)$ を、新たな次数 $t$ の多項式で $n$ 人に再分散する
1. 各 $P_j$ が、受け取った $n$ 個のシェアをラグランジュ係数 $\lambda_i$ で重み付けして足す

<Details title="なぜこれで次数が下がるのか">

復元は $xy = \sum_{i=1}^{n} \lambda_i v_i$ という**$v_i$ の線形結合**である。そして線形結合は秘密分散のシェアのままローカルに計算できる。

$P_i$ が $v_i$ を次数 $t$ の多項式 $h_i$ で再分散したとする。$P_j$ が受け取るのは $h_i(j)$ たちである。ここで

$$
H(x) = \sum_{i=1}^{n} \lambda_i h_i(x)
$$

とおくと、$H$ は次数 $t$ の多項式の線形結合なので**次数 $t$ 以下**であり、しかも

$$
H(0) = \sum_i \lambda_i h_i(0) = \sum_i \lambda_i v_i = xy
$$

を満たす。$P_j$ が計算する $\sum_i \lambda_i h_i(j) = H(j)$ はまさに $H$ の $j$ でのシェアである。つまり全員がローカルな足し算をするだけで、次数 $t$ の $[xy]$ が手に入る。

$\lambda_i$ が $v_i$ の値に依らず公開値であることが、この議論を可能にしている。Gennaro–Rabin–Rabin (1998) はこの手順を最適化して、乗算 1 回あたりの通信量を大きく減らした。

</Details>

乗算 1 回につき各参加者が $O(n)$ 個の体の元を送るので、通信量は $O(n^2)$、ラウンド数は 1 である。全体のラウンド数は**回路の乗算深さ**に比例し、回路の大きさ (ゲート数) には比例しない。深さの浅い回路に書き換えることが、そのまま高速化になる。

<Hint level="info">
  BGW が耐えられる結託人数は、semi-honest なら $t < n/2$、malicious なら $t < n/3$ である。
  この差は「正しく再分散したか」を検証する必要から来ており、検証可能秘密分散 (VSS) を使って埋める。

$t < n/2$ という条件は、**正直者多数**があってはじめて情報理論的に安全な MPC ができるという一般論と対応している。参加者が 2 人 ($n = 2$, $t = 1$) の場合はこの条件を満たせないので、次の Beaver triple や garbled circuit のような計算量的仮定に基づく道具が必要になる。

</Hint>

## Beaver triple

次数低減は正直者多数を前提にする。2 者計算や不正者多数でも乗算を実現する、より汎用的な仕掛けが Beaver (1991) の**乗算三つ組 (Beaver triple)** である。

発想は「**難しい部分を、入力を知る前に済ませてしまう**」ことにある。$c = ab$ を満たす乱数の組 $(a, b, c)$ のシェア $[a], [b], [c]$ を事前に配っておけば、本番の乗算は次の恒等式に帰着する。

$$
xy = \big((x - a) + a\big)\big((y - b) + b\big) = de + d\,b + e\,a + ab
\qquad \text{where} \quad d = x - a, \; e = y - b
$$

$d$ と $e$ さえ公開されれば、右辺は $[a], [b], [c] = [ab]$ の**線形結合**なので、ローカルに計算できてしまう。

![Beaver triple による乗算のプロトコル](/img/mpc-beaver.svg)

```python
def beaver_multiply(xs, ys, triple, p=P):
    """加法的シェア [x], [y] から [xy] を作る。triple = ([a], [b], [c]), c = ab。"""
    a_s, b_s, c_s = triple
    # d, e は全員に公開される (実際には部分シェアを送り合って復元する)
    d = sum(x - a for x, a in zip(xs, a_s)) % p
    e = sum(y - b for y, b in zip(ys, b_s)) % p
    return [
        # 定数項 de は二重に足さないよう 1 人だけが加える
        (c + d * b + e * a + (d * e if i == 0 else 0)) % p
        for i, (a, b, c) in enumerate(zip(a_s, b_s, c_s))
    ]
```

安全性は明快である。$a$ と $b$ は一様乱数なので、公開される $d = x - a$ と $e = y - b$ は $x, y$ をワンタイムパッドでマスクした値であり、それ自体は一様分布する。**三つ組を 1 回きりで使い捨てる**限り、入力は漏れない。

<Hint level="warn">
  同じ三つ組を 2 回使うと即座に破綻する。$x$ と $x'$ に同じ $a$ を使えば $d - d'
  = x - x'$ が公開され、
  入力の差分が漏れる。ワンタイムパッドの鍵の使い回しとまったく同じ失敗である。
</Hint>

この構成の実務上の価値は、**オフライン・オンライン分離**にある。三つ組の生成は入力に依存しないので、暇なときに大量に作り貯めておける。生成には準同型暗号や OT を使うので重いが、オンラインの乗算は数回の加算と 1 ラウンドの通信で終わる。SPDZ (Damgård–Pastro–Smart–Zakarias, 2012) はこの路線を突き詰め、シェアに情報理論的 MAC を付けることで**不正者多数かつ malicious** な設定まで対応した。

## 紛失通信 (OT)

Beaver triple の生成をはじめ、2 者計算のほとんどの土台になるのが**紛失通信 (oblivious transfer, OT)** である。1-out-of-2 OT の仕様はこうである。

- 送信者 $S$ は 2 つのメッセージ $m_0, m_1$ を持つ
- 受信者 $R$ は選択ビット $b \in \{0, 1\}$ を持つ
- 実行後、$R$ は $m_b$ **だけ**を知り、$S$ は $b$ について**何も**知らない

![公開鍵を使った 1-out-of-2 OT のプロトコル](/img/mpc-ot.svg)

図の構成 (Even–Goldreich–Lempel, 1985) では、受信者が「自分は片方の秘密鍵しか持っていない」という状況を自分で作り出す。$pk_{1-b}$ を秘密鍵を知らないまま生成できること、そして $pk_0$ と $pk_1$ が見分けられないことが要になっている。

<Hint level="info">
  Kilian (1988) は **OT だけあれば任意の関数の秘匿計算ができる**ことを示した。この意味で OT は MPC における
  完全なプリミティブである。

一方で OT は公開鍵演算を必要とするので重い。IKNP (Ishai–Kilian–Nissim–Petrank, 2003) の **OT extension** は、$\kappa$ 回 (128 回程度) の「本物の」OT を種にして、そこから対称鍵暗号だけで何百万回もの OT を作り出す。現代の実装が現実的な速度で動くのは、ほぼこの技術のおかげである。

</Hint>

## Yao の garbled circuit

2 者計算にはもうひとつ古典的な解法がある。Yao (1986) の**garbled circuit (混乱回路)** である。BGW が「値を分散する」のに対し、こちらは「**回路そのものを暗号化する**」。

回路作成者は、各ワイヤの $0$ と $1$ に対してそれぞれランダムな鍵 (ラベル) を割り当てる。そして各ゲートの真理値表の各行を、入力ワイヤの鍵 2 つで出力ワイヤの鍵を暗号化したものに置き換え、行をシャッフルする。

![AND ゲートの真理値表を鍵で暗号化してシャッフルした garbled table](/img/mpc-garbled-circuit.svg)

評価者は入力ワイヤの鍵を 2 つ持っている。それで 4 行すべてを復号しようとすると、対応する 1 行だけが正しく開き、出力ワイヤの鍵が手に入る。**開いた行がどの入力の組み合わせだったかは分からない**まま、次のゲートへ進める。

評価者が自分の入力に対応する鍵を受け取る部分には OT を使う。鍵は 2 つのうち片方だけを、しかも自分の入力ビットを作成者に知られずに得なければならないので、これはまさに 1-out-of-2 OT である。

主な最適化を挙げておく。

- **point-and-permute** (Beaver–Micali–Rogaway, 1990): 鍵の末尾 1 ビットで開くべき行を指示する。4 回の復号試行が 1 回で済む
- **free-XOR** (Kolesnikov–Schneider, 2008): 鍵を $k^1 = k^0 \oplus \Delta$ と取ると、XOR ゲートが暗号文なしで評価できる。**XOR が無料になる**
- **half-gates** (Zahur–Rosulek–Evans, 2015): AND ゲートあたりの暗号文を 2 個に削減する。近年は 1.5 個に減らす構成も知られている

|            | GMW / BGW 系         | garbled circuit       |
| ---------- | -------------------- | --------------------- |
| ラウンド数 | 回路の乗算深さに比例 | **定数** (2 ラウンド) |
| 通信量     | ゲートあたり小さい   | ゲートあたり鍵 2 個分 |
| 得意な回路 | 深さが浅く幅が広い   | 深いが小さい          |
| 参加者数   | 任意                 | 基本は 2 者           |

ネットワークの遅延が大きいほど garbled circuit が有利になり、帯域が細いほど秘密分散が有利になる、と覚えておくとよい。

## 準同型暗号

ここまでは参加者どうしの通信で計算していたが、**暗号文のまま計算できる暗号**があれば、計算そのものを外部のサーバに丸投げできる。これが**準同型暗号 (homomorphic encryption)** である。

### 加法準同型: Paillier

Paillier 暗号 (1999) は加法準同型の代表格である。$n = pq$ を RSA と同じように取り、平文空間を $\Bbb{Z}_n$、暗号文空間を $\Bbb{Z}_{n^2}^{\ast}$ とする。$g = n + 1$ とすると $g^m \equiv 1 + mn \pmod{n^2}$ なので、暗号化は

$$
\mathrm{Enc}(m) = (1 + mn) \cdot r^n \bmod n^2
$$

と書ける。$r$ は $\Bbb{Z}_n^{\ast}$ から一様に選ぶ乱数で、これが入るので同じ平文でも毎回違う暗号文になる (**確率的暗号**)。ここから

$$
\mathrm{Enc}(m_1) \cdot \mathrm{Enc}(m_2) = \mathrm{Enc}(m_1 + m_2), \qquad
\mathrm{Enc}(m)^k = \mathrm{Enc}(km)
$$

が直ちに従う。**暗号文の掛け算が平文の足し算に、暗号文のべき乗が平文の定数倍に対応する**。

```python
def encrypt(pk, m, rng):
    n, n2 = pk
    r = rng.randrange(1, n)
    return (1 + m * n) * pow(r, n, n2) % n2

def add(pk, c1, c2):
    return c1 * c2 % pk[1]    # 平文の加算

def mul_const(pk, c, k):
    return pow(c, k, pk[1])   # 平文の定数倍
```

安全性は**判定合成剰余仮定 (DCRA)**、大雑把には「$\Bbb{Z}_{n^2}^{\ast}$ の元が $n$ 乗数かどうか判定するのは難しい」という仮定に基づく。加算と定数倍だけあれば内積が計算できるので、電子投票の集計や、線形モデルの推論には十分である。

### 乗法準同型と完全準同型

ElGamal 暗号は $\mathrm{Enc}(m_1) \cdot \mathrm{Enc}(m_2) = \mathrm{Enc}(m_1 m_2)$ という乗法準同型をもつ (平文を $g^m$ に載せる指数 ElGamal にすれば加法準同型になるが、復号に離散対数を解く必要があり平文空間が小さくなる)。教科書的な RSA も乗法準同型だが、決定的なので意味論的安全性がなく、そのままでは使えない。

加算と乗算の**両方**が任意回数できるものを**完全準同型暗号 (fully homomorphic encryption, FHE)** といい、Gentry (2009) が初めて構成した。現代の FHE はすべて格子暗号に基づき、暗号文に小さなノイズを載せている。ここに本質的な困難がある。

![準同型演算のたびにノイズが増え、bootstrapping でリセットする様子](/img/mpc-fhe-noise.svg)

加算ではノイズはほぼ足し算だが、乗算ではノイズが掛け算的に増える。ノイズが一定の閾値を超えると復号できなくなるので、素朴には**あらかじめ決めた深さまでしか計算できない** (これをレベル付き準同型暗号という)。

Gentry の突破口が **bootstrapping** である。復号回路そのものを準同型に評価する、つまり「暗号化された秘密鍵を使って、暗号文の中で復号を実行する」と、ノイズの溜まった暗号文が、ノイズの小さい新しい暗号文に生まれ変わる。これで任意深さの計算が可能になる。代償はコストで、bootstrapping 1 回は素の演算よりはるかに重い。

| 方式      | 得意なデータ | 特徴                                                                           |
| --------- | ------------ | ------------------------------------------------------------------------------ |
| BGV / BFV | 整数         | SIMD で数千スロットを一括処理。深さを決めて bootstrapping を避ける使い方が主流 |
| CKKS      | 実数 (近似)  | 誤差を許す代わりに実数演算が自然。機械学習の推論向き                           |
| TFHE      | ブール値     | ゲート 1 個ごとに高速な bootstrapping。任意深さの回路に強い                    |

## どれくらい重いのか

手元で実測してみる。加法的秘密分散 ($\Bbb{Z}_p$, $p = 2^{61} - 1$) と、素朴に実装した Paillier を比較した。

![秘密分散と Paillier 暗号の 1 演算あたりの所要時間](/img/mpc-benchmark.svg)

Apple M4 Pro + CPython 3.9 での結果はこうなった。

| 演算          | 秘密分散        | Paillier 1024 bit  | Paillier 2048 bit   |
| ------------- | --------------- | ------------------ | ------------------- |
| 分散 / 暗号化 | $0.29 \, \mu s$ | $9{,}304 \, \mu s$ | $70{,}028 \, \mu s$ |
| 加算          | $0.46 \, \mu s$ | $8.99 \, \mu s$    | $31.6 \, \mu s$     |
| 復元 / 復号   | $0.12 \, \mu s$ | $9{,}415 \, \mu s$ | $72{,}230 \, \mu s$ |
| 1 個のサイズ  | 8 B             | 256 B              | 512 B               |

読み取れることは 3 つある。

- **暗号文どうしの加算だけなら、Paillier もそれほど遅くない** (2048 bit で $32 \, \mu s$、秘密分散の約 70 倍)。大量の値を足し合わせるだけの用途なら十分実用になる
- **暗号化と復号が桁違いに重い**。$n^2$ を法とする $n$ ビット指数のべき乗が入るためで、2048 bit では 1 回 70 ms もかかる。入出力の回数が多い処理には向かない
- **データが 64 倍に膨らむ**。秘匿計算のボトルネックは計算量ではなく通信量になりがちで、この差はそのまま効いてくる

<Hint level="warn">
  この計測は素朴な純 Python 実装なので、絶対値そのものには意味がない。実用ライブラリは CRT による復号の高速化、
  固定底のべき乗の事前計算、乱数 $r^n$ の使い回し防止つき事前生成などで一桁以上速い。
  見るべきは**演算ごとの比**であり、「加算は安いが暗号化・復号は高い」「暗号文は大きい」という構造の部分である。

一方で秘密分散の側は、この表に**通信時間が含まれていない**。乗算のたびに 1 ラウンドの通信が入るので、
LAN でも 1 回あたり数百 $\mu s$、WAN なら数十 ms が乗る。実際の勝負はそこで決まる。

</Hint>

## 使い分け

| 手法                    | 参加者                | ラウンド数     | 向いている場面                             |
| ----------------------- | --------------------- | -------------- | ------------------------------------------ |
| 加法的秘密分散 + Beaver | 任意 (不正者多数可)   | 乗算深さに比例 | 汎用。SPDZ 系の実装が充実                  |
| Shamir + BGW            | 3 者以上 (正直者多数) | 乗算深さに比例 | 情報理論的安全性が欲しいとき               |
| garbled circuit         | 2 者                  | 定数           | 遅延の大きい回線、比較・ソートなど深い回路 |
| 加法準同型暗号          | 委託先 1 つ           | 1 往復         | 集計・内積のみ。通信を減らしたいとき       |
| FHE                     | 委託先 1 つ           | 1 往復         | 相手と対話できない委託計算                 |

大まかな指針はこうである。**参加者どうしが同時にオンラインでいられるなら秘密分散系が速い**。相手が計算を代行するだけの受動的なサーバなら準同型暗号を選ぶ。比較・大小判定・ソートのようにビット演算が多い処理は、算術回路と相性が悪いので garbled circuit かビット分解を検討する。

## 周辺の技術との関係

- **秘匿積集合演算 (private set intersection, PSI)**: 2 者が集合の共通部分だけを知るプロトコル。汎用 MPC でも書けるが、専用構成のほうが桁違いに速い代表例
- **ゼロ知識証明**: 「知っていること」を明かさず証明する。semi-honest なプロトコルに malicious 耐性を足す部品として使われる
- **差分プライバシー**: 守る対象が違う。秘匿計算は**計算過程**からの漏洩を防ぐが、出力そのものからの漏洩は防げない。出力にノイズを載せる差分プライバシーと組み合わせて、はじめて全体が守られる
- **連合学習 (federated learning)**: 勾配だけを集約する枠組みで、それ自体は秘匿計算ではない。勾配から学習データが復元できる攻撃が知られており、集約部分に秘匿計算 (secure aggregation) を使うのが定石
- **TEE (Intel SGX など)**: ハードウェアで隔離された領域で平文のまま計算する。圧倒的に速いがハードウェアベンダを信頼する必要があり、サイドチャネル攻撃の報告も多い

## 実装上の注意

- **乱数の質**: 秘密分散の安全性は乱数が一様であることに全面的に依存する。`random` モジュールのような疑似乱数ではなく、必ず暗号論的に安全な乱数 (`secrets`, `/dev/urandom`) を使う
- **法のサイズと桁あふれ**: $\Bbb{Z}_p$ 上の計算は数値がすぐ $p$ の近くまで大きくなる。固定小数点で実数を扱うときは、乗算のたびにスケールが二乗になるので切り捨て処理が必要になる
- **semi-honest 前提の危うさ**: 不正な参加者が 1 人でも嘘のシェアを送ると、結果が静かに壊れる。しかも誰が壊したか分からない。検証可能秘密分散や MAC は「オプション」ではなく、脅威モデル次第では必須である
- **出力からの漏洩**: 前述のとおりプロトコルが完璧でも、$f$ の選び方が悪ければ入力は復元できる。「何人以上のデータがなければ集計を返さない」といった出力側の設計も含めて考える
- **タイミング・サイドチャネル**: シェアの値に依存して分岐したり、実行時間が変わったりすると、そこから情報が漏れる。定数時間実装が求められる

## まとめ

- 秘匿計算とは「全員が信頼する第三者」を暗号技術で置き換えることであり、安全性は理想世界のシミュレーションで定義される
- 秘密分散は加算と定数倍を通信ゼロで実現する。$k - 1$ 個のシェアからは情報理論的に何も分からない
- 難しいのは乗算で、Shamir では次数低減、加法的シェアでは Beaver triple を使う。ラウンド数は回路の乗算深さで決まる
- 2 者計算では OT と garbled circuit の組が定数ラウンドを実現する。OT は MPC における完全なプリミティブである
- 準同型暗号は計算を丸ごと委託できるが、暗号化・復号のコストとデータ膨張、そして FHE ではノイズ管理の重さが代償になる
- どれを選ぶかは、参加者の構成・ネットワークの遅延と帯域・脅威モデルの 3 つで決まる
