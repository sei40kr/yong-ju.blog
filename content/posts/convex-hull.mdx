## 凸包とは

### 凸集合

集合 $C \subseteq \Bbb{R}^d$ が**凸集合 (convex set)** であるとは、任意の 2 点を結ぶ線分がふたたび $C$ に含まれること、すなわち

$$
\bold{x}, \bold{y} \in C, \; \lambda \in [0, 1] \implies \lambda \bold{x} + (1 - \lambda) \bold{y} \in C
$$

が成り立つことをいう。

![凸集合では 2 点を結ぶ線分が常に内部に収まるが、凸でない集合でははみ出す](/img/hull-convex-set.svg)

### 凸包

点集合 $S \subseteq \Bbb{R}^d$ の**凸包 (convex hull)** $\mathrm{conv}(S)$ とは、$S$ を含む最小の凸集合、つまり $S$ を含むすべての凸集合の共通部分である。

$$
\mathrm{conv}(S) = \bigcap \{ C \mid S \subseteq C, \; C \text{ は凸集合} \}
$$

凸集合の共通部分はふたたび凸集合なので、これは確かに凸集合であり、定義から「$S$ を含む凸集合のうち最小のもの」になっている。

同じものは、**凸結合 (convex combination)** を使って下から構成することもできる。

$$
\mathrm{conv}(S) = \left\{ \sum_{i=1}^k \lambda_i \bold{x}_i \; \middle| \; k \in \Bbb{N}, \, \bold{x}_i \in S, \, \lambda_i \ge 0, \, \sum_{i=1}^k \lambda_i = 1 \right\}
$$

<Details title="2 つの定義が一致することの証明">

右辺を $H$ と書く。

**$H \subseteq \mathrm{conv}(S)$**: $S$ を含む任意の凸集合 $C$ は凸結合について閉じている ($k$ に関する帰納法。$k = 2$ は凸集合の定義そのもので、$\sum_{i=1}^{k} \lambda_i \bold{x}_i = (1 - \lambda_k) \sum_{i=1}^{k-1} \frac{\lambda_i}{1 - \lambda_k} \bold{x}_i + \lambda_k \bold{x}_k$ と分解すれば $k - 1$ の場合に帰着する)。よって $H \subseteq C$ であり、そのような $C$ すべての共通部分をとっても $H \subseteq \mathrm{conv}(S)$ である。

**$\mathrm{conv}(S) \subseteq H$**: $H$ 自身が凸集合であることを示せばよい。$H$ の 2 元の凸結合は、係数を掛け合わせればふたたび $S$ の元の凸結合になるからである。$H$ は $S$ を含む凸集合なので、共通部分である $\mathrm{conv}(S)$ は $H$ に含まれる。

</Details>

### 有限点集合の凸包

以下では $d = 2$、$S$ は $n$ 個の点からなる有限集合とする。このとき $\mathrm{conv}(S)$ は凸多角形になり、その頂点は必ず $S$ の点である。

![点集合とその凸包。凸包の頂点になる点と、内部に埋もれる点がある](/img/hull-definition.svg)

凸包の頂点になる点を**極点 (extreme point)** という。極点とは「他の点の凸結合として表せない点」であり、直感的には**釘を打った板に輪ゴムをかけたとき、輪ゴムが引っかかる釘**である。

計算幾何のアルゴリズムで「凸包を求める」というときは、この頂点列を**反時計回り (または時計回り) の順に並べて出力する**ことを指す。以下、点の個数を $n$、凸包の頂点数を $h$ と書く。$h$ は入力によって $3$ から $n$ まで変化する。

<Hint level="info">
  凸包は計算幾何の「まず最初にやること」として非常に応用が広い。

- 最遠点対 (直径) の計算 — 最遠点対は必ず凸包の頂点どうしである
- 最小外接長方形・最小包含円などの外接図形
- 2 つの凸多角形の交差判定 (GJK アルゴリズム、物理エンジンの衝突判定)
- 線形計画問題の実行可能領域の可視化、多面体の頂点列挙
- DP の高速化 (Convex Hull Trick)、外れ値の除去

</Hint>

## 準備: 3 点の向き判定

すべての凸包アルゴリズムの土台になるのが、**3 点がどちら回りに並んでいるか**の判定である。$\bold{o}, \bold{a}, \bold{b} \in \Bbb{R}^2$ に対し、外積の $z$ 成分

$$
\mathrm{cross}(\bold{o}, \bold{a}, \bold{b}) = (a_x - o_x)(b_y - o_y) - (a_y - o_y)(b_x - o_x)
$$

の符号を見ればよい。

![外積の符号で 3 点の向きが判定できる](/img/hull-orientation.svg)

| 符号                 | 意味                                                     |
| -------------------- | -------------------------------------------------------- |
| $\mathrm{cross} > 0$ | $\bold{o} \to \bold{a} \to \bold{b}$ は反時計回り (左折) |
| $\mathrm{cross} < 0$ | 時計回り (右折)                                          |
| $\mathrm{cross} = 0$ | 3 点は一直線上                                           |

言い換えると、$\mathrm{cross}(\bold{o}, \bold{a}, \bold{b}) > 0$ は「$\bold{b}$ が有向直線 $\bold{o} \to \bold{a}$ の**左側**にある」ことを意味する。

```python
def cross(o, a, b):
    """o->a と o->b の外積 (z 成分)。正なら o->a->b は反時計回り。"""
    return (a[0] - o[0]) * (b[1] - o[1]) - (a[1] - o[1]) * (b[0] - o[0])
```

<Hint level="info">
  $\frac{1}{2} \mathrm{cross}(\bold{o}, \bold{a}, \bold{b})$ は三角形 $\bold{oab}$ の**符号付き面積**でもある。
  向き判定と面積計算が同じ 1 本の式で書けるのは、外積が「平行四辺形の符号付き面積」だからである。

この式は**加減乗算しか使っていない**ことが重要である。座標が整数なら結果も整数になり、判定に一切の誤差が入らない。競技プログラミングで座標を整数のまま扱うのはこのためである。

</Hint>

## ギフト包装法 (Jarvis march)

最も素朴なアルゴリズムは、**贈り物を包装紙で包む**ように、外側から 1 頂点ずつ辿っていくものである。

1. 最も左 (同点なら最も下) の点を選ぶ。この点は必ず凸包の頂点である
1. 現在の点 $\bold{p}$ から、**他のすべての点が直線 $\bold{p} \to \bold{q}$ の左側に来る**ような点 $\bold{q}$ を探す。これが次の頂点である
1. 出発点に戻るまで繰り返す

![ギフト包装法は現在の頂点から最も外側の点を選ぶ操作を繰り返す](/img/hull-jarvis.svg)

```python
def jarvis_march(points):
    """反時計回りの凸包頂点列を返す。O(nh)。"""
    start = min(points)  # 最も左下の点は必ず凸包の頂点
    hull = []
    p = start
    while True:
        q = next(r for r in points if r != p)
        for r in points:
            # r が p->q の右側にあるなら、より外側の r に乗り換える
            if cross(p, q, r) < 0:
                q = r
        hull.append(p)
        p = q
        if p == start:
            return hull
```

<Details title="なぜ最も左の点が凸包の頂点なのか">

$\bold{p}$ を $x$ 座標最小の点とし、$\bold{p}$ が他の点 $\bold{x}_i$ の凸結合 $\bold{p} = \sum \lambda_i \bold{x}_i$ で書けたとする。$x$ 座標を比べると

$$
p_x = \sum_i \lambda_i (x_i)_x \ge \sum_i \lambda_i p_x = p_x
$$

であり、等号成立には $\lambda_i > 0$ なるすべての $i$ で $(x_i)_x = p_x$ が必要である。$y$ 座標も最小に取っておけば同様の議論で $\bold{x}_i = \bold{p}$ となり、$\bold{p}$ は他の点の凸結合では表せない。よって $\bold{p}$ は極点である。

</Details>

内側のループは $n$ 回、外側のループは凸包の頂点数だけ回るので、計算量は $\bold{O(nh)}$ である。凸包の頂点が少ない ($h$ が小さい) 入力では $O(n)$ 近くまで速くなる一方、すべての点が円周上にあるような入力では $h = n$ となり $O(n^2)$ に退化する。

このように**出力サイズ $h$ に計算量が依存する**アルゴリズムを**出力鋭敏 (output-sensitive)** という。

## Graham スキャン

$O(n \log n)$ を達成する古典的なアルゴリズムが Graham スキャンである。アイデアは「一度ぐるっと並べてから、へこんでいる点を捨てる」ことにある。

1. 最も下の点 $\bold{p}_0$ を基準点として選ぶ
1. 残りの点を $\bold{p}_0$ から見た**偏角の順**にソートする
1. その順に点を走査し、スタックに積む。ただし**新しい点を加えると右折になる**とき、右折が解消されるまでスタックの先頭を pop する

![偏角ソートしてから走査し、右折になる点を捨てる](/img/hull-graham.svg)

pop の判定はもちろん向き判定でできる。スタックの上位 2 つを $\bold{s}_{-2}, \bold{s}_{-1}$、新しい点を $\bold{p}$ として、$\mathrm{cross}(\bold{s}_{-2}, \bold{s}_{-1}, \bold{p}) \le 0$ なら $\bold{s}_{-1}$ を捨てる。

計算量はソートの $O(n \log n)$ が支配する。走査部分は一見二重ループだが、**各点は高々 1 回しか pop されない**ので、pop の総回数は $n$ 回以下である (償却解析)。したがって走査は $O(n)$ で終わる。

<Hint level="warn">
  偏角ソートを `atan2` の値で行うのは誤差の面で危険である。実務では
  「$\bold{p}_0$ から見て点 $\bold{a}$ が点 $\bold{b}$ より偏角が小さい」を
  $\mathrm{cross}(\bold{p}_0, \bold{a}, \bold{b}) > 0$ という比較関数で表し、外積だけでソートする。
  これなら整数演算のまま完結する。

また、偏角が同じ点が複数ある場合の順序 (基準点から近い順か遠い順か) を決めておかないと、共線の点があるときに結果が壊れる。

</Hint>

## Andrew の monotone chain

Graham スキャンの偏角ソートを、**単なる座標のソート**に置き換えたものが Andrew の monotone chain である。実装が短く、誤差にも強いので、実用上はこれが第一選択になる。

1. 点を $(x, y)$ の辞書順でソートする
1. 左から右へ走査して、右折を pop しながら**下側チェーン**を作る
1. 右から左へ同じことをして**上側チェーン**を作る
1. 2 つのチェーンを連結する

![x 座標でソートし、下側チェーンと上側チェーンを別々に作って連結する](/img/hull-monotone-chain.svg)

```python
def convex_hull(points):
    """反時計回りの凸包頂点列を返す。O(n log n)。"""
    pts = sorted(set(points))
    if len(pts) <= 2:
        return pts

    def build(seq):
        chain = []
        for p in seq:
            # 右折 (または一直線) になったら手前の点を捨てる
            while len(chain) >= 2 and cross(chain[-2], chain[-1], p) <= 0:
                chain.pop()
            chain.append(p)
        return chain

    lower = build(pts)
    upper = build(reversed(pts))
    # 連結部の重複 (両端の点) を除いてつなぐ
    return lower[:-1] + upper[:-1]
```

<Hint level="info">
  `<= 0` を `< 0` に変えると、**辺の上に乗っている点も出力に含まれる**ようになる。
  「凸包の頂点だけが欲しい」のか「凸包の境界上の点をすべて列挙したい」のかで使い分ける。
  面積や周長を求めるだけなら前者、格子点の数え上げなどでは後者が必要になることがある。
</Hint>

<Details title="下側チェーンが下側凸包を与えること">

$x$ でソートされた点列を左から処理するとき、スタックが常に「左折だけからなる列 (下に凸な鎖)」に保たれることは、pop の条件から明らかである。示すべきは、pop された点が下側凸包の頂点でないことである。

点 $\bold{b}$ が $\mathrm{cross}(\bold{a}, \bold{b}, \bold{c}) \le 0$ によって pop されたとする ($\bold{a}$ はスタック上で $\bold{b}$ の 1 つ下、$\bold{c}$ は新しい点)。$x$ 座標の順に処理しているので $a_x \le b_x \le c_x$ であり、このとき $\mathrm{cross}(\bold{a}, \bold{b}, \bold{c}) \le 0$ は「$\bold{b}$ が線分 $\bold{ac}$ の上側 (または線分上) にある」ことと同値である。つまり $\bold{b}$ より下に $\bold{a}, \bold{c}$ を結ぶ線分が存在するので、$\bold{b}$ は下側凸包の頂点ではない。

いったん pop された点が後から復活することもない。以降に現れる点は $\bold{c}$ 以上の $x$ 座標をもち、$\bold{b}$ をますます線分の上側に取り残すだけだからである。

上側チェーンについても左右を反転すれば同じ議論が成り立つ。下側凸包と上側凸包を連結したものが凸包全体である。

</Details>

## QuickHull

クイックソートと同じ「分割して征服する」発想のアルゴリズムである。

1. $x$ 座標が最小の点 $\bold{a}$ と最大の点 $\bold{b}$ を取る。両方とも凸包の頂点である
1. 直線 $\bold{ab}$ の上側にある点のうち、**直線から最も遠い点** $\bold{c}$ を選ぶ。これも凸包の頂点である
1. 三角形 $\bold{abc}$ の内側にある点はすべて捨てる
1. 線分 $\bold{ac}$ の外側、線分 $\bold{cb}$ の外側について再帰する。下側も同様に処理する

![最遠点で三角形を作り、その内側の点を捨てて再帰する](/img/hull-quickhull.svg)

点から直線までの距離は、外積の絶対値 $|\mathrm{cross}(\bold{a}, \bold{b}, \bold{p})|$ の比較で済む (分母の $\| \bold{b} - \bold{a} \|$ は共通なので不要)。

うまく分割できれば $T(n) = 2 T(n/2) + O(n)$ から $O(n \log n)$ になるが、クイックソートと同じく**最悪 $O(n^2)$** である (毎回 1 点しか削れない場合)。実データでは三角形の内側の点が一気に消えるため非常に高速で、しかも**次元によらず同じ考え方が通用する**ため、3 次元以上の実装 (有名な `qhull`、SciPy の `scipy.spatial.ConvexHull` の中身) はこの系統である。

## 分割統治法

マージソートのように、点集合を左右に二分してそれぞれの凸包を求め、あとで貼り合わせる方法もある。

1. $x$ 座標でソートし、左半分と右半分に分ける
1. 再帰的にそれぞれの凸包を求める
1. 左右の凸包を結ぶ**上接線**と**下接線**を求め、その内側になった辺を捨てて 1 つの凸包にする

![左右の部分凸包を上下 2 本の接線で貼り合わせる](/img/hull-divide-conquer.svg)

接線は、両方の凸包の頂点を交互に動かして「もう回せない」状態まで進める貪欲法で $O(n)$ 時間に求められる。よって $T(n) = 2 T(n/2) + O(n) = O(n \log n)$ である。

2 次元では monotone chain のほうが実装が簡単だが、この方法は**3 次元の凸包を $O(n \log n)$ で求める**アルゴリズムの基礎になる。

## Chan のアルゴリズム

ギフト包装法の $O(nh)$ と Graham スキャンの $O(n \log n)$ を組み合わせて、$\bold{O(n \log h)}$ を達成するのが Chan のアルゴリズムである。

1. パラメータ $m$ を決め、点を $\lceil n / m \rceil$ 個のグループに分ける
1. 各グループの凸包を Graham スキャンで求める。$O((n/m) \cdot m \log m) = O(n \log m)$
1. 全体の凸包をギフト包装法で辿る。ただし次の頂点を探すとき、各部分凸包について**二分探索で接点を求める** ($O(\log m)$) ので、1 ステップは $O((n/m) \log m)$
1. $m$ ステップ以内に一周できなければ $m$ を大きくしてやり直す

![部分凸包を作ってからギフト包装することで、1 ステップのコストを下げる](/img/hull-chan.svg)

ステップ数を $m$ で打ち切るのがポイントである。$m \ge h$ ならその回数で一周できるので、全体の計算量は

$$
O(n \log m) + O\left( m \cdot \dfrac{n}{m} \log m \right) = O(n \log m)
$$

となる。$m$ を $2^{2^t} \; (t = 1, 2, \dots)$ と**二重指数的に大きくしながら**試すと、失敗した試行のコストも含めて

$$
\sum_{t=1}^{\lceil \log \log h \rceil} O(n \log 2^{2^t}) = \sum_{t=1}^{\lceil \log \log h \rceil} O(n 2^t) = O(n 2^{\log \log h + 1}) = O(n \log h)
$$

に収まる (等比数列の和は最終項の定数倍)。

## 計算量の下界

比較や四則演算を単位時間とするモデル (代数的決定木モデル) では、凸包の計算に $\Omega(n \log n)$ の時間が必要である。**ソートが凸包に帰着できる**からである。

実数 $x_1, \dots, x_n$ をソートしたいとする。これを放物線上の点

$$
\bold{p}_i = (x_i, x_i^2)
$$

に写すと、$y = x^2$ は狭義凸なので**すべての点が凸包の頂点になる**。したがって凸包を左端から反時計回りに出力すれば、それは $x_i$ をソートした列そのものである。凸包が $o(n \log n)$ で解けるならソートも $o(n \log n)$ で解けてしまい、ソートの下界 $\Omega(n \log n)$ に矛盾する。

出力鋭敏なアルゴリズムに対しては $\Omega(n \log h)$ が下界となることが知られており、Chan のアルゴリズムは**この意味で最適**である。

## どれを使うべきか

実際に手元で計測してみる。ギフト包装法と monotone chain を同じ Python 実装で比較した。

![点の分布によってギフト包装法の実行時間が大きく変わる](/img/hull-benchmark.svg)

円板内に一様分布する点では凸包の頂点数の期待値が $\Theta(n^{1/3})$ にしかならず ($n = 8000$ で実測 $h = 63$)、ギフト包装法もそこそこ動く。しかし全点が円周上にある最悪ケースでは $h = n$ となり、$n = 8000$ で 2000 倍以上の差がついた。$\Theta(n^2)$ と $\Theta(n \log n)$ の違いがそのまま現れている。

<Hint level="info">
  この計測の絶対値は「ソートは C 実装、走査は Python
  実装」という言語事情も含んでいるので、 グラフの高さではなく**傾き
  (漸近的な増え方)** を見てほしい。
</Hint>

| アルゴリズム             | 計算量                             | 特徴                                                   |
| ------------------------ | ---------------------------------- | ------------------------------------------------------ |
| ギフト包装法             | $O(nh)$                            | 実装が最も簡単。$h$ が小さいと分かっているとき         |
| Graham スキャン          | $O(n \log n)$                      | 古典。偏角ソートの扱いに注意が必要                     |
| Andrew の monotone chain | $O(n \log n)$                      | **実用上の第一選択**。座標ソートだけで済み、実装も短い |
| QuickHull                | 平均 $O(n \log n)$ / 最悪 $O(n^2)$ | 実データで高速。高次元に一般化しやすい                 |
| 分割統治法               | $O(n \log n)$                      | 3 次元 $O(n \log n)$ への足がかり                      |
| Chan のアルゴリズム      | $O(n \log h)$                      | 理論的に最適。実装は重い                               |

## 実装上の落とし穴

計算幾何のバグはほとんどが**縮退 (degeneracy) と誤差**から生まれる。凸包も例外ではない。

- **点数が 3 未満**: 空・1 点・2 点のときに何を返すかを決めておく。多くの実装は点列をそのまま返す
- **重複点**: 同じ座標の点があると外積が $0$ になり、pop の条件によっては無限ループや不正な出力になる。あらかじめ重複を除いておくのが安全 (上のコードで `sorted(set(points))` としているのはこのため)
- **共線点**: すべての点が一直線上にあるとき、凸包は「多角形」にならない。上のコードは両端の 2 点を返す
- **浮動小数点誤差**: 外積の符号判定が誤ると、凸性が壊れて出力が閉じないという致命的な失敗が起きる。整数座標なら整数演算のまま、そうでなければ誤差 $\varepsilon$ を導入するか、Shewchuk の robust predicates のような適応精度演算を使う
- **オーバーフロー**: 座標が $10^9$ 程度あると外積は $10^{18}$ 程度になる。64 bit 整数のぎりぎりなので、座標の平行移動などで桁を落としておく

<Hint level="warn">
  $\varepsilon$
  による比較は「近ければ等しい」という**推移律を満たさない**関係を作ってしまう。
  ソートの比較関数に $\varepsilon$ を持ち込むと、実装によっては未定義動作 (C++
  の `std::sort` など) に踏み込む。
  誤差の扱いは、判定の一貫性まで含めて設計する必要がある。
</Hint>

## 凸包から先へ

凸包が求まると、その上を歩くだけで解ける問題が一気に増える。

- **最遠点対 (直径)**: 凸包上を 2 つのポインタで回す**回転キャリパス (rotating calipers)** により、凸包が求まったあと $O(h)$ で求まる
- **最小面積外接長方形**: 最適な長方形の 1 辺は必ず凸包のいずれかの辺と重なる (Toussaint)。これも回転キャリパスで $O(h)$
- **凸多角形の内外判定**: 1 頂点から見た扇形の二分探索で $O(\log h)$
- **Convex Hull Trick**: 直線群 $y = a_i x + b_i$ の最小値の包絡線は下側凸包そのもの。DP の遷移を $O(\log n)$ に落とす典型手法
- **3 次元以上**: 3 次元の凸包の面数はオイラーの公式から $O(n)$ で、$O(n \log n)$ で構成できる。一般の $d$ 次元では上限定理 (Upper Bound Theorem) により面数が $O(n^{\lfloor d/2 \rfloor})$ まで増えうる

## まとめ

- 凸包は「点集合を含む最小の凸集合」であり、有限点集合では凸多角形の頂点列として出力する
- すべてのアルゴリズムの土台は外積による向き判定であり、整数座標なら誤差なく計算できる
- ギフト包装法 $O(nh)$ → Graham スキャン / monotone chain $O(n \log n)$ → Chan $O(n \log h)$ という改良の系譜がある
- 下界はソートからの帰着で $\Omega(n \log n)$、出力鋭敏なら $\Omega(n \log h)$
- 実装では縮退と誤差の扱いがすべてであり、迷ったら monotone chain を整数座標で使う
